## Mine App 5.0.7 · 双版本更新

### 双版本共同改动

**进程数只在「会刷新」的缓存态隐藏**

5.0.6 改成「用缓存渲染时隐藏进程数」，但漏了一种情况：**1 分钟内的新鲜缓存不会触发刷新**（`load()` 里直接 return），于是进程数永远不出现了。

现在按「这次会不会刷新」区分：

| 缓存状态 | 会不会刷新 | 进程数 |
|---|---|---|
| 1 分钟内的新鲜缓存 | **不会**（直接用它） | **显示**（沿用上次的数据） |
| 超过 1 分钟的过期缓存 | 会（先画旧图，后台刷新） | 先隐藏，刷新后显示 |
| 没有缓存 | 会 | 无旧数据可显示 |
| 手动刷新 / 操作后 | 会 | 拿到新数据后显示 |

判据就是 `restoreCache` 内部那个 `fresh` 标志：

```js
if (!fresh && d.apps) for (var i = 0; i < d.apps.length; i++) d.apps[i].procs = 0;
```

**实测**（模拟器，1 分钟内重启 App）：

```
QQ
com.tencent.mobileqq
314M · 5.3% · 4s · 2procs ›     ← 新鲜缓存直接显示进程数
```

而过期缓存那条路径（5.0.6 验证过）仍然是「先隐藏、刷新后出现」。
