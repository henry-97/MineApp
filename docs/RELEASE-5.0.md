## Mine App 5.0 · 双版本更新

### 双版本共同改动

**1. 限制不再「用一次就失效」——新增墓碑补做**

4.9.3 把「限制」换成了墓碑机制（`am set-inactive`），但留下一个问题：**这个标记会被系统自动清除**。

Android 的设计是「用户主动启动应用时，把它从 inactive 状态里拿出来」——否则你打开的应用会被自己冻住。结果是：

```
设置限制 → 应用被冻结（oomAdj 900+）
用户打开一次 → 系统自动激活它
退出后 → 限制没了，应用照常跑
```

实测：同一个应用，设置后是 `oomAdj 915`（cached），打开再退出后变成 `701`（previous），界面上却还显示「已限制」。

**现在**：每次全量刷新（亮屏 3 分钟 / 熄屏 30 分钟）时，对**已限制且当前仍有进程**的应用重新执行一次 `am set-inactive`。

| 项 | 实测 |
|---|---|
| 需要补做的包 | 41 个（当前有进程的已限制应用） |
| 单次耗时 | 1.7 ~ 2.2 秒 |
| 执行方式 | 一条 shell 批量执行（比逐条快 3 倍） |
| 没有进程的包 | 直接跳过 |

这个动作**没有独立定时器**，挂在全量刷新的分支里——以后调整刷新频率，补做自动跟着变。

**耗电**：App 自身 CPU 时间从约 7 分钟/天增加到 14 分钟/天（翻倍），折算成整机电量约 **+0.8%**。翻倍听起来多，但基数很小，仍不到整机的 1%。

**2. 每个应用有几个进程，现在能看到并展开**

列表里多进程的应用会在时间后面标 `4进程 ›`，点开是这个应用的进程明细：

```
微信
1754M · 11.6% · 26m · 4进程 ⌄

● push·多开     3m    169M   oom600
● push         11m    209M   oom500
● 主进程        1m   1017M   oom500
● 主进程·多开   <1m    824M   oom600
```

每一列分别是：活动状态（绿点）、子进程名、累计 CPU 时间、内存、系统 oom 档位。

- **只显示多进程的应用**：单进程是常态，每行都标「1进程」只会占地方
- **`·多开` 标注**：应用双开 / 手机分身的进程与主空间同名，不标会看起来像重复。实测系统里有 `User 0（机主）` 和 `User 999（XSpace）` 两套
- **数据只在点开时查询**，后台不刷新

**3. 清理更彻底：连最近任务卡片一起清**

`am force-stop` 只杀进程，多任务界面里的卡片还留着（实测：进程 0 个，卡片仍在）。现在 force-stop 之后会再执行一次 `am stack remove <taskId>`，把卡片一并删掉。

点行右侧的 × 之后：

1. **立刻**摘掉「N 进程」标注、收起已展开的进程面板
2. **0.8 秒后**整行从列表移除（留一下让你看清是哪一行）
3. 后台异步执行 force-stop + 清卡片，不弹确认、不报释放量

下次刷新时后端如实返回。

**4. 一些细节调整**

- 内存单位从 `MB` 简化为 `M`（`1801M`），时间从 `26 m` 简化为 `26m`，进程数从 `4 进程` 简化为 `4进程`
- CPU 时间按分钟展示：`<1m` / `11m` / `4h52m` / `>24h`
- 活跃绿点口径统一：进程行有绿点，应用行也一定亮（原来 `prev` 状态被排除，会出现「进程亮、包名不亮」的矛盾）
- 进程面板里不再有 × —— 无 root 时 Android 不允许杀别的应用的单个进程（`kill -9` 直接 `Operation not permitted`），留着会名不副实
