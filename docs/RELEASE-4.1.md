# Mine App 4.1（多通道版）

> 本版是 `com.henry.appmanager.multi`，可与标准版共存。
> **ADB / Shizuku 两条通道都适用本次优化** —— 两版共用同一套后台服务。

## 后台能耗大幅下降

两处改动，直接砍掉后台开销：

**① 读内存不再走 shell**

以前后台每 3 秒执行一次 `cat /proc/meminfo`，走 Shizuku / ADB 时等于每 3 秒 fork 一个进程 —— 这是待机耗电的主要来源（Shizuku 通道下尤其明显）。

现在改用系统 API（`ActivityManager.MemoryInfo`），读的是系统侧同一份数据，零进程开销。

**② 刷新频率按可见性分档**

| 设备状态 | 刷新间隔 |
|---|---|
| 屏幕亮 + App 在前台 | 3 秒 |
| 屏幕亮 + App 在后台 | 15 秒 |
| 屏幕熄灭 | 60 秒 |

点亮屏幕会立即补刷一次，不用等下一轮。

实测（Shizuku 通道）：后台 45 秒内的 shell 调用从 **15 次降到 0 次**。

## 主界面内存实时更新

主界面底部的「内存 x/yG (p%)」以前只在手动刷新列表时才更新，而通知栏每 3 秒跳一次，同一屏上两个数字各走各的。

现在由后台服务查完直接推给页面 —— 不轮询、不重复查，**且只在前台推**。后台时界面不可见，推过去只是空跑；通知栏照常更新。
