## Mine App 5.0.9 · 双版本更新

### 双版本共同改动

这一版是 5.0.8 的收尾：把「限制」的判定改宽，并修掉一个会让解除限制失效的 bug。

**1. 不再要求所有命令都成功**

以前「限制」只认一条：索引标记有没有写进去。只要这条失败，界面就报「操作失败」——哪怕待机分组已经落到最严档、另外几条后台权限也都打上了。

现在改成**任意一条落地就算成功**（白名单踢掉 / 分组落到最严档 / 任意一条后台权限写进去）。不同 ROM 对个别命令的支持程度不一样，这样就不会因为某一条不适用而整笔失败。

分组没到最严档时仍然记一条日志，但只留痕、不影响结果。

**2. 修复：解限后几秒又被重新限制**

这不是命令失败，而是缓存问题。补做限制读的是内存里的名单缓存，而它只在全量刷新时重新查询。解限成功后界面立刻刷新，紧接着的列表请求拿着**还没更新的旧名单**又补了一次，把刚解除的限制原样打回去——实测解限成功后不到 4 秒就被复原。

修了两处：

- 限制 / 解限成功后立刻更新内存缓存；
- 加版本号保护：全量刷新查询名单要跑一次 shell（约 0.5 秒），期间若发生过限制 / 解限，就丢弃这次查询结果，等下一轮对齐（否则旧结果会覆盖刚做的改动）。

**实测**（Redmi / HyperOS 3.0 / Android 15）：

| 步骤 | 结果 |
|---|---|
| 解限哔哩哔哩 | 分组 45 → 10，四条后台权限全部放开 |
| 等待 200 秒（跨两轮补做，均不含该应用） | 仍是 10 / allow，**没有被复原** |
| 重新限制 | 分组回到 45，四条权限全部 ignore，界面提示「限制完成：成功 1 个」 |
| 顶部统计 | 110 个，与操作前一致 |

**3. 文档**

中英文 README 已同步到 5.0.8 引入的新限制机制（移出电池优化白名单 → 写最严待机档 → 四条后台权限），并补上「限制会先把它移出白名单、解除时加回去」这一条互斥关系，以及「限制会让应用收不到推送，需要收消息请解除限制」。
