# Mine App 4.9.1 · 双版本更新

> 一个 Release 挂两个 APK，按**包名**选你要的那个：
> `MineApp-4.9.1.apk`（经典版） / `MineApp-4.9.1-multi.apk`（多通道版）。

## 双版本共同改动

### 修复：应用查找只能索引到首屏

**现象**：建完索引后，只能搜到桌面第一页的应用，其他页的一个都找不到。

**原因**：当桌面读不到页码时，代码会改用「滑动数页数」。数页数需要一个判断“这一屏还是不是桌面”，用的是**两页之间有没有同名应用图标**。

HyperOS 桌面上，如果两页的应用完全不重名，这个判断就会得出“已经滑出桌面了”，**第一页就停手，总页数被算成 1**。

**修复**：改成查顶层 Activity 是不是 Launcher 包名（`dumpsys activity` 的 `topResumedActivity`）——这是系统级的权威判断，不受页面内容影响。

**顺带修**：主循环原本写死最多 8 页，桌面超过 8 页时后面永远索引不到。已放宽到 20 页。

> 🔴 **升级后请重新建一次索引**（设置 → 初始化应用查找功能 → 开始）。旧索引是按“1 页”建的，不重建仍然搜不到后面的应用。

### 修复：免责声明弹窗过段时间又出现

**现象**：明明点过「同意并使用」，过了几天打开 App 又弹一次。

**原因**：「已同意」标记只存在 WebView 的 `localStorage` 里。Android 会在存储紧张时清理 WebView 数据，标记一没就重新弹。

**修复**：

- 点「同意」时同时写 `localStorage` 和 App 私有的 SharedPreferences
- 启动时本地标记没了，就去问 SharedPreferences；只要后端说同意过，**补回本地标记、不弹窗**

SharedPreferences 是 App 私有数据，不会被 WebView 清理影响，所以以后不会再无缘无故弹第二次。

## 经典版（`com.henry.appmanager`）

两个修复都生效。索引走的是「无障碍 + 逐页遍历」，页数探测逻辑与多通道版共用同一份代码。

## 多通道版（`com.henry.appmanager.multi`）

两个修复都生效。如果用的是 Root 通道，索引走的是直读 `launcher.db`，不经过页数探测，本来就不受这个 bug 影响；ADB / Shizuku 通道与经典版相同。
