## Mine App 5.0.3 · 双版本更新

### 双版本共同改动

**迁移改成「一直等到通道就绪」，不再等几秒就放弃**

5.0.2 里把固定等 3.5 秒改成了最多等 10 秒，但仍然不够——首次安装后 Shizuku 的 binder 可能十几秒才送达，超时就跳过，用户看到的是「装了但什么都没发生」。

现在改成**一直等到通道可用再迁移**：

```java
int waited = 0;
while (!"ok".equals(state())) {
    if (waited >= 1800) return;                       // 半小时还没通道 = 根本没配
    int step = waited < 10 ? 2 : (waited < 60 ? 5 : 30);
    Thread.sleep(step * 1000L);
    waited += step;
}
// 通道就绪 → 执行迁移 → 成功才写布尔标记
```

间隔逐步拉长：

| 阶段 | 查询间隔 | 理由 |
|---|---|---|
| 前 10 秒 | 2 秒 | Shizuku binder 通常几秒内到，快速抓住就绪瞬间 |
| 10 秒 ~ 1 分钟 | 5 秒 | 还在等，但不必那么密 |
| 1 分钟以后 | 30 秒 | 可能是 ADB 通道需要用户手动连 |

**保留 30 分钟上限**：如果用户根本没配通道（没装 Shizuku、ADB 也没连过），无限等待只是白占一个后台线程。半小时足够覆盖所有正常情况。

**迁移成功才写标记**：`allOk` 为 false 时不写，下次启动会重新等通道、重新执行。不会留下「迁了一半」的状态。
