# Mine App 4.5（多通道版）

> 本版是 `com.henry.appmanager.multi`，可与标准版共存。

## 修复 4.4 的更新检查缺陷

4.4 在挑选 Release 时只看「有没有 `multi-v*`」，没看「这个版本是不是比当前新」。

结果：只要历史上存在过 `multi-v4.4`，多通道版就会一直停在它上面，ver 一直是 4.4，前端判断「已是最新」—— **之后发布的任何版本都再也收不到**。

4.5 加了版本过滤：只有比当前版本新的 Release 才算数，旧的直接跳过，继续往下找。

## 为「合并发布」做准备（本版仍用旧格式）

现在每个版本会发两个 Release（`v4.x` 和 `multi-v4.x`），在 Releases 列表里被分成两块，**多通道版容易沉到下面找不到**。以后打算改成一个 Release 挂两个 APK，用户只看一个页面就能选。

切换格式会有断档风险：已装的旧版只会找自己那个 tag 前缀（多通道版只认 `multi-v*`）。所以 **4.5 作为桥接版**——

- **发布仍用旧格式**：`v4.5` + `multi-v4.5`，保证 4.4 及更早的多通道用户能检测到本版
- **代码已能识别新格式**：找不到「比当前版本新的 `multi-v*`」时，会回落到「带 `-multi.apk` 资产的 `v*`」，并只挑里面的多通道包（不会装成标准版）

这样一来，下一个版本就可以只发一个 Release 了，链条不会断。

> 本版的更新检查行为与之前一致，你不需要做任何操作。
